## Domain and integration

`src/content/quests.json` supplies two small original engine fixtures, Camp introductions and Field practice. These exercise prerequisites and all four objective kinds without introducing the D06 Act1 story. Explicit acceptance starts future-event counting; a prerequisite unlocks only after its reward is claimed. Multiple active quests are supported; one tracked quest is persisted. Ready quests claim safely at camp, with no cancellation that could reset a one-time ledger.

Travel comes from successful world transitions, interaction from validated nearby camp dialogue, defeat from current-tick player-attributed hostile deaths, and collection from successful inventory pickup. Unique actor/item IDs prevent repeated events and drop/repick inflation. Collection means acquisition in the named area; it does not consume the item or require a newly generated item. This supports recovery of an existing item as well as natural loot. Quest counters are bounded identity ledgers, retained independently for each objective. No clocks or unseeded randomness enter simulation.

Rewards reuse existing XP/point arithmetic, gold and deterministic item generation/placement. An optional item uses a pinned content3 reliquary stream, distinct from the unchanged global encounter stream. It appears nearby with the existing capacity/navigation/ownership checks; inventory need not be empty. Full ground capacity, a conflicting item identity, gold overflow or failed XP preparation leaves every reward half and the ready ledger unchanged. An existing atomic character checkpoint captures the ledger, XP, gold and item ownership together. Failed IndexedDB writes retain the ordinary unsaved-session/export/recovery policy; this is not a separate storage engine.

Exploration6 adds strict quests1 state. Exploration1–5 explicitly migrate to no accepted quests, retaining maps/seeds/encounters/meetings/expedition/items and character schema5. Save validation rejects malformed/duplicate objective identities, impossible counters, missing prerequisite claims, inconsistent statuses/tracking, missing world visit/meeting/death evidence and claimed rewards with insufficient combined quest/expedition XP. The checksum detects corruption, not authentication. Existing raw quarantine, backup and CAS policies remain unchanged.

Quest IDs, objective ordering/counts, prerequisites and reward values are persistence contracts. Future content appends new definitions; changing an existing contract requires an explicit migration. Preserve these fixtures when adding D06 content. No escort AI, reputation simulation, procedural quests, vendors or new item registry. Existing art/controller/hardware/GPU follow-ups remain open. Journal graphics and fixture text are project-authored code/prose; no external assets or new placeholders.

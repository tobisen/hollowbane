# DBL-290 — Controller identity and readiness

User follow-up: Auto reports Unknown layout; the controller name contains Xbox; after selecting/saving a device, settings later show #0 not connected. Exact native id/mapping/axes/buttons were requested. Do not claim an unknown physical layout is fixed from browser emulation.

Confirmed software boundaries:

- Selecting a device name is separate from selecting its input layout. Auto only accepts browser-standard mappings or explicitly registered vendor profiles; brand recognition alone does not establish raw button/axis order. Manual Xbox/PlayStation/generic overrides remain available. Settings now explain this distinction and show the current readiness cause.
- Browser indexes are session slots, not durable device identity. Explicit selections now persist the reported ID alongside their index hint and follow that ID across reindexing. An unrelated controller that reuses the old index is ignored. Identical devices with identical reported IDs remain indistinguishable beyond the current slot hint; no physical identity guarantee is claimed.
- Legacy v1 index-only settings migrate without losing layout, axes or remaps. Identity is captured once the selected device is visible. New settings preserve a Saved entry when the API temporarily exposes no device, rather than implying physical disconnection. Auto stays automatic.
- getGamepads may return an empty list until a controller gesture is observed by the current document. See [Gamepad API specification](https://www.w3.org/TR/gamepad/). Waiting, blocked access, missing API, unsupported layout and neutral rearm are now distinct diagnostic states. Saved manual overrides survive a reload and delayed API visibility. The touch/click settings entry remains available for configured devices while waiting.
- Phaser's optional native gamepad plugin directly polls the API. A blocked API caused the movement scene to fail startup despite the separate diagnostics page working. Native polling is now enabled only after a safe capability probe; keyboard/mouse scene startup remains usable when access is denied. The semantic adapter retains its guarded polling. API error details and effective configuration are exposed in Live controller state.

Tests: two additional deterministic unit cases cover index reuse/reconnect and migration (135 total unit tests pass). Browser cases cover an unmapped Xbox-named snapshot, explicit and automatic selection, saving an override, reloading into an empty API, restoring the same ID at a different index, refusing an unrelated replacement, actual actor movement, and permissions-policy denial with working keyboard fallback. The blocked-startup case failed before the Phaser capability guard. Targeted new cases pass in Chromium, Firefox and WebKit. Complete regression/publication evidence follows below.

No arbitrary nonstandard Xbox/handheld profile is guessed. A native raw snapshot is still needed to distinguish four-axis standard-compatible data from layouts that expose triggers among aim axes or different physical button order. Physical follow-ups DBL-282–286 remain unverified.

Complete local controller regression: 25 Chromium cases and 48 Firefox/WebKit behaviors pass after the final changes. Full check/format: 135 unit tests, strict typecheck/lint/build, asset/backlog validation. New readiness screenshot reviewed. User confirms a friend is testing and has been asked for native metadata; physical-device compatibility remains unverified. Publication results follow below.

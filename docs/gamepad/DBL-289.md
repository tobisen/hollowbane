# DBL-289 — Gameplay controller focus

User reports controller movement/buttons work in diagnostics but not gameplay. Investigation reproduced a real input-routing defect using the same browser adapter as the game. It does not establish the user's exact hardware-specific cause; controller/browser details were requested separately.

Before repair: focus the game field, press D-pad Up, then move the left stick. Global UI navigation handled D-pad actions even while gameplay owned focus, focused a page control, then set blockGameplay. Raw controller diagnostics kept updating while movement was blocked. The new regression fails before repair with the world field unexpectedly inactive.

Repair: UI directional navigation runs only with an open modal or when UI already owns focus. Gameplay D-pad semantic actions no longer focus page controls. Menu/settings navigation, explicit UI focus and safe pause/disconnect behavior remain unchanged. No mapping, combat or movement formula change.

Regression exercises all four D-pad directions, verifies focus remains in gameplay, then verifies actual rendered actor movement in cloister, combat and monster scenes. Full check/format passes 133 unit tests. Chromium controller suite passes 21 cases. Full Firefox/WebKit suite passes 40 cases, plus the new diagnostics-return fixture passes both browsers; Chromium adds the same fixture for 22 total cases. This fixture navigates with the controller from diagnostics to gameplay without forcing game-field focus. Initial fixture assumed a specific initial browser focus; it now navigates from actual focus. Publication results follow below. This is virtual API/browser verification, not physical-controller verification.

User clarified that Auto reports Unknown layout and a saved index later appears not connected. This is separate compatibility/lifecycle evidence and is not explained by the focus fix. Exact native id/mapping/axes/buttons were requested; do not claim the physical-device issue resolved.

Publication: runtime 87d9342 passed CI/Pages [39032057748](https://github.com/tobisen/hollowbane/actions/runs/39032057748). The follow-up DBL-290 adds identity/readiness handling; native hardware metadata remains pending.

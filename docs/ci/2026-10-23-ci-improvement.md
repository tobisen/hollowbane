## Implementation and release contract

| Tier        | Required before Pages                                                                                                                                                                                         | Hosted after Pages                                                          |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| Fast        | TypeScript/lint/format, release tooling, stable critical units plus directly affected unit tests, one sealed production build, exact-artifact load plus genuine controller lock/skill-damage smoke            | Verify exact SHA and every sealed byte; same two stable browser smoke cases |
| Integration | Fast checks plus domain and reverse-import affected units; all affected browser files across up to two isolated single-worker runners                                                                         | Same exact-byte and two-case hosted gate                                    |
| Full        | Static/core/build/smoke once; all units, validators/orchestrator/tooling, **all175 existing Chromium cases** across four balanced single-worker runners, and all15 required Chromium/Firefox/WebKit contracts | Same exact-byte and two-case hosted gate                                    |

All pre-existing scenarios, assertions, snapshot contracts, per-case deadlines and serial saved journeys are retained. Full remains available/required for milestones and broad/unknown/shared changes; Deep is unchanged. A failing, cancelled or skipped required Integration/Full job blocks `verify`, which blocks Pages; failed/missing hosted acceptance fails the release. No author-supplied “fast” or “integration” label can lower risk.

The planner compares parsed before/after public TypeScript declarations, including internal type aliases, instead of treating any changed line containing `export` as an API break. Explicitly typed implementation/configuration values can use Integration when their contracts are unchanged; changed signatures/types, inferred return expressions, save/migration/serialization/version content, unknown inputs, deletions, tooling/dependencies, shared combat/controller foundations and >35 transitive unit consumers or more than three domain groups still require Full. Parsed imports add affected unit/fixture consumers; changed browser helpers run every dependent browser file. Domain groups cover boss/combat, campaign, world/navigation, ownership/persistence, UI/controller and rendering. An unmapped test helper fails closed. The exact last accepted CI+Pages+hosted ancestor remains the base, including previously failed/cancelled changes. Missing/untrustworthy history requires Full.

Full no longer repeats the complete affected integration suite first. Hosted tests test publication with a genuine stable gameplay interaction, while the appropriate pre-deploy tier protects affected behavior. Four Full runners and two Integration runners each use **one** browser worker, avoiding competing software renderers on one VM. Updated whole-file timing weights preserve hooks/order and cover every file once. The build is sealed once and reused by all jobs. npm caching was already effective and remains. Locked browser binaries are now cached; OS libraries/fonts still install, using the primary HTTPS Ubuntu archive rather than the slow Azure HTTP mirror. The official exact-version Playwright container returned404, so no mismatched image or browser version was substituted. Push/PR triggers and cancel-obsolete concurrency remain; no duplicate release was found among the ten audited pushes.

The IndexedDB campaign helper previously booted an unused complete Phaser game solely to open the origin, then booted the actual saved game. It now loads an intercepted empty setup document, seeds **real** IndexedDB with the same transaction and then loads the unmocked game. All restore/class/level/area/hostile-AI assertions remain. This is test setup only, with no game-state mutation after loading.
